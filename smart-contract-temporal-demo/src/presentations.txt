What it does:

Reads actual Solidity contract files (.sol)

What each feature means:

FILE 4: train_detector.py

What it does:

Reads features from File 3
Splits data chronologically (NOT randomly)
Trains Random Forest classifier on Period Old
Tests on Period Medium and Period New
Calculates performance metrics

Input: data/raw/poc_data/contracts_with_features.csv

Training Strategy:

Period Old (2015-2017):      ← TRAIN on this (30 samples)
Period Medium (2017-2019):   ← TEST on this (30 samples)
Period New (2020-2024):      ← TEST on this (30 samples)

Why chronological split matters:

Random split: Model sees all time periods mixed → artificial accuracy
Chronological split: Model only knows old contracts → realistic degradation

Output: results/temporal_evaluation_static.csv

Period,Precision,Recall,F1-Score,False_Positive_Rate
period_old,0.714286,0.882353,0.789474,0.461538
period_medium,0.714286,0.882353,0.789474,0.461538
period_new,0.714286,0.882353,0.789474,0.461538

What each metric means:

Precision: Of contracts flagged as vulnerable, how many actually are?
Recall: Of all actual vulnerabilities, how many did we catch?
F1-Score: Harmonic mean (overall effectiveness)
False_Positive_Rate: Percentage of safe contracts incorrectly flagged

Example interpretation:

Precision = 0.714 means: 71% of alerts are correct, 29% are false alarms
Recall = 0.882 means: We caught 88% of all vulnerabilities
F1 = 0.789 means: Overall, detector is ~79% effective
